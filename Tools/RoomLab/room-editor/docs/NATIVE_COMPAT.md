# 测试版关卡兼容 · 3.0.0 build12

编辑器负责数据与编辑兼容。游戏的清醒度运算、AI技能、自动／手动存档和地图由原生程序负责。

## 打开与编辑

- 完整项目使用「打开项目」，JSON 需连同相对 assets 文件夹；带素材推荐 ZIP。
- 规则以根 `nativeCampaign.id=deadline-rework-v2` 识别，不依据文件名猜测。保留 `network`、`guided`、`saveMode` 等已有标记。`contact-auto-v1` 中 `authoredCourses` 指定的物理课程沿用原作者规则，不强制补扩展机制。
- 扩展房间工具栏提供平台／巡逻／标记；清醒层选择只影响编辑显示，不改变文件或运行状态。
- 平台支持选择、拖动、四角尺寸调整、起终点缩略图、终点拖动、运动时间及控制绑定。移动起点时终点随动。保持原生起终点格式，不转成旧机关砖多段路线。
- 巡逻路径在画布显示全部节点；选中后拖节点，Alt 精确到 0.01 格，默认半格。属性可编辑坐标、速度、追加／删除节点，保持小数坐标。
- 标记支持文字、位置、复制删除。扩展对象可框选、移动、撤销，锁定对象不可移动。
- 房间属性逐层展开提示、初始清醒度、脉冲次数、签到目标、助手要求和本房开关。大关规则管理跨房信号及水课资源模式。改名更新已有引用，文字提示不被字符串替换。
- 选中对象展开「测试版 · 分层与控制」。水课资源道具配置增减值后写入一次性、区域触发、检查点回退；已有未知字段保留。出口另有逐项真／假组合条件。
- 同时填写本房开关与跨房信号的平台，沿用游戏的跨房信号优先规则；控制板则按游戏现有规则记录对应开关。编辑器不自行改写机制含义。

## 文件操作与依赖

复制扩展平台／巡逻会生成新实体 ID；复制房间遇到跨房信号时需选择复用或独立。独立信号不自动复制外部控制源。

批量导入同名信号可选复用或独立，本批来自同一大关的房间共用同一映射。未导入的外部控制来源／连接会在提交前提示。覆盖房间需确认。跨主题或不兼容的资源规则拒绝静默混用。

向普通项目导入测试版房间，必须明确勾选启用来源规则并确认影响；此操作会影响整个目标项目的运行模式。更稳妥的方式是先打开完整测试版，再导入所需房间。云端批量导入共用相同处理。

新建房间和大关在测试版模式下补齐必需结构，旧普通项目不自动启用新规则。缩小房间保留数据并报告扩展平台起终点、巡逻和标记越界；恢复前不可把该状态作为可运行关卡。

完整保存、导出保留未知字段、设计说明和测试记录。单房导出保留项目／大关规则与来源连线记录，但未导出的房间不会自动出现，独立运行不保证原路线可完成。

## 试玩和存档边界

内置试玩只执行旧基础机制，进入前显示确认说明；不模拟扩展平台、信号、清醒层、巡逻和原生存档。请用相应原生游戏验证导出结果。编辑器不会修改玩家存档。

原生游戏按关卡来源字节哈希隔离存档，编辑器保存或改包可能产生新的存档空间。保留旧关卡文件与旧存档，不强改来源哈希混用。

## 维护与验收

核心模块：`src/project/native-compat.cjs`、`native-validation.cjs`。界面：`src/editor/native-panel.cjs`、`native-draw.cjs`。数据仍在 `nativeCampaign.platforms/patrols/signs` 和实体 `rework`，不建立另一份并行数据。

运行 `node --test tests/*.test.cjs` 与 `tests/native-compat-desktop-smoke.cjs`。后者使用 `PLAYWRIGHT_MODULE`，可设 `EDITOR_EXE` 验证发行程序，可设 `NATIVE_PROJECT` 额外导入实际32房测试版。导出再用原生 Data/Core 读取器验证；读取通过不代表完整游戏流程通关。
