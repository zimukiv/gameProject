# Room Lab 2.5.5

本版以 2.5.4 修正版为基础，整合朋友修改的 2.5.2 玩法；保留云连接修复、房间多选导入/覆盖、标签排序、路径回放与命名等现有功能。没有改动云端网站或现有云端节点。

## 使用

解压完整程序包，打开 RoomLab.exe。通过「导入项目包」打开随交付提供的 `RoomLab-2.5.5-兼容存档.zip`；或「打开项目」选择修复目录下的 project.json，assets 必须同行保留。请将本版程序和修复存档一起发给队友。

## 玩法

- 「流程与存档」新增存档点。触发后记录本房间复活位置、资源、积分和机关快照；重试仍遵循每个机关的回退策略。免费冲刺和三次计数按原规则刷新。
- 存档点是本次试玩检查点，不是关闭程序后的进度存档；进入其他房间后以新房间入口为检查点。
- 新放方块（含存档点）仍默认实心，可在基础属性切换。实心存档点在顶面复活，空心存档点在内部复活；朋友原存档的空心状态保留。
- 电磁装置「行为」新增「允许左右侧面接触启动」。侧面容差 8 世界像素，与缩放无关；空心装置仍支持重叠触发。普通旧关卡默认关闭此扩展。
- 喷气板按方向显示箭头；任何方向都遵循碰撞开关，不强制覆盖用户选项。触发与碰撞保持独立。

## 兼容规则

关卡仍为 version=2。普通 v1/v2 继续原迁移链。未携带 compatibility.runtime 且含 common.checkpoint 的 v2 文件识别为本次朋友修改版：首次读取把左右喷气板物化为 collision=false、trigger.mode=region，并给该文件的轨道写入 params.sideTrigger=true。完成后标记 compatibility.runtime=2.5.5、importedProfile=friend-2.5.2，后续读取保留手工修改。

新建项目带 runtime 标记，因此新添加存档点不会被误识别为朋友旧版。没有存档点签名的其他未知分支不自动猜测；可手工修改轨道侧面触发和碰撞设置。未知扩展字段保留，明确不支持的模块主版本继续拒绝运行。

导出和云保存声明 common.checkpoint 1.0；启用侧面触发的轨道声明 physics.rail 2.0。新版轨道接受原 1.x。旧程序可能打开编辑数据，但不能等价运行新增机关，双方应升级到 2.5.5。

读取旧云端节点时先验证原始快照，再在内存中升级。旧快照的字节和指纹保持不变，不覆盖云端历史；显式保存仍在所选/上次读取版本下产生新节点。

## 指定存档修复

原文件不覆盖。修复副本保留 11 房间、10 接线、7 存档点、9 素材、16 条试玩路径及现有 ID。「AI追逐1」温控区原 x=-1、宽44，裁剪为 x=0、宽43，保留房间内原覆盖范围。常规导入不会自动裁剪其他越界设计数据。

升级脚本：`node scripts/upgrade-friend-project.cjs input.json NEW-output-directory`。脚本拒绝已有输出目录，检查素材/依赖/试玩结构，输出 project.json、assets、完整 ZIP 和升级报告。它不上传云端，也不改原文件。

## 验证范围

核心测试覆盖迁移幂等、模块声明、碰撞独立、复活资源/状态与原数据保留。桌面 UI 检查全部 11 个房间启动，以及测试房间中真实按键触发存档点和重试、侧面触发开关。不是对全部关卡逐房通关或难度认证。
