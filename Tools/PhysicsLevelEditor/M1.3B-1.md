# M1.3B-1 Level1 reconstruction candidate

This stage uses the audited M1.2 Level1 V3 draft, not the original Scene as an import template. `tools/prepare-m13b-level1.py` derives two independent candidates under `Levels/Drafts/M1.3B/`. It leaves the M1.2 draft and all formal Scenes unchanged.

## Current status and data authority

- The baseline contains all 71 source GameObjects, 254 source component IDs, and 597 source component reference entries. Its `dataStatus: m13bCandidate` means **structured native field input prepared; Unity behavior has not been verified**.
- `component.data.fields` supplies native Unity serialized values. `component.data.references` supplies stable ID targets in the original field order. `ObjectV3` supplies name, active, tag, layer, parent/sibling order and Transform/RectTransform data. The importer creates new GameObjects and components, then applies fields, then binds references. The immutable `sourceSerialized` backup is checked by hash and never replayed to the new components.
- The edited candidate changes Start ground object `46c11342-6027-593d-87d5-ff1d6cb512b2` local X from `-5` to `-4.5`, and Air vent object `fa949e9b-1ebb-54c1-b252-8ae8a737e2b3` `AirVentBlock.upwardForce` from `19` to `20`. The importer rejects any other difference between these two candidates.
- `Level1.coverage.json` enumerates 39 actual component types, 3,072 native top-level field candidates and 71 Transform components with preserved-only Unity metadata fields. Structural Transform/hierarchy fields use the object-level V3 fields. Original scene settings are still `sourceOnly`; public-system template slots are still `pendingTemplate`. Their source records are preserved, but no full Level1 restoration or Play Mode PASS is claimed.
- The M1.3A static-collider Density warning was caused by calling Unity 6's `Collider2D.density` setter for colliders without a dynamic Rigidbody2D using auto-mass. The revised seven-object importer sets density only when the API permits it; otherwise it verifies the audited value already equals the collider's default. This needs another Unity Editor run to verify that the warning is gone.

## Isolation and Unity menu

Before copying the new C# script, its `.meta`, both candidate JSON files, the coverage report, and the unchanged M1.2 Level1 draft to `Temp/Phase4AIsolatedProject`, close that project's Unity Editor. Preserve existing scenes, logs, marker, Company/Product and `.meta` files. The new importer requires the exact isolation marker, Company/Product values and the audited Level1 Scene and M1.2 draft SHA-256 values. It creates a uniquely named `Assets/Scenes/LevelEditorM13B_Level1_<GUID>.unity` only if all pre-save checks pass. A failure reports the field path and generated path; do not use a failed scene as evidence.

In the isolated Unity Editor, use these menu entries in order:

1. `Physics Level Editor > M1.3B-1 > Attempt isolated Level1 baseline rebuild`.
2. `Physics Level Editor > M1.3B-1 > Attempt isolated Level1 edited rebuild`.

Expected when an attempt passes its **candidate** checks: `M13B1_ISOLATION_PASS`, then `M13B1_CANDIDATE_STATUS=PASS` with `objects=71`, `sourceComponents=254`, `nativeFields=COMPARED`, `references=COMPARED`. The importer compares V3 values in Unity before and after saving and reopening its new Scene. It then deliberately emits `M13B1_DATA_STATUS=INCOMPLETE` and `M13B1_PLAY_STATUS=NOT_RUN`, because source-only scene settings and unverified runner templates remain. A `M13B1_CANDIDATE_STATUS=FAIL` line includes the first unsupported or mismatched field path.

After a successful edited rebuild, inspect Start ground's local X (`-4.5`) and Air vent's `upwardForce` (`20`) in the generated Unity Scene. The baseline scene should retain `-5` and `19`. Do not modify or save a formal Scene. Play Mode validation of the complete level remains pending until all native fields, scene settings and public-system bindings pass the Editor data gate.

`npm.cmd run check`, `npm.cmd run build`, `python tools/compile-m13a-static.py`, and `python tools/compile-m13b-static.py` are static checks only. An actual Unity Editor menu result and a separate Play Mode result are required before M1.3B-1 can be accepted as complete.
