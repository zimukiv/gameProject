# M1.1 source contract (design only)

`Levels/ProjectManifest.json` names three fixed rooms. All are `sourceOnly` and have a null `levelDataPath`. `Levels/SourceMaps/*.source.json` record every source GameObject and component in the three unchanged Unity scenes. The scenes and their SHA-256 hashes remain the authoritative serialized configuration until a later migration produces verified V3 level files. These source maps are traceability indexes, not playable levels.

## Ownership and restoration

| Code | Meaning | M1.1 responsibility |
| --- | --- | --- |
| A | Editable level object | `levelObjects.<objectId>`; component adapter pending |
| B | Reference marker | `referenceMarkers.<objectId>`; stable target pending |
| C | Runner common system | `runnerBindings.<objectId>` plus `templateSlot`; template binding pending |
| D | Scene config and visual object | `sceneConfigVisual.<objectId>`; configuration adapter pending |

Each component has its own source fileID, componentId, Unity type, original order, source document hash, ownership and pending restoration status. Non-GameObject Unity scene settings remain protected by the source scene hash and by `LevelDataV3.sceneConfig` with `sourceOnly` status. No current file claims to reconstruct them. The complete original configuration must remain available until its V3 adapter is proven. `RectTransform` and `Canvas` belong to runner or scene configuration handling, not ordinary world coordinates.

## Identity and references

Existing three Level1 object IDs come from `Level1.ids.json`. Other source object IDs are UUIDv5 of `object:<sceneGuid>:<gameObjectFileId>` using the fixed namespace in `identity-v3.ts`. Component IDs are UUIDv5 of `component:<sceneGuid>:<gameObjectFileId>:<componentFileId>`. New editor objects and components get random UUIDs and no fabricated Unity source fileID. Display names do not identify objects.

Source maps record fileID references as ordered field paths with explicit `null`, object, component, scene setting or asset kinds. A lost reference ID must fail validation; only an original `fileID: 0` becomes explicit null. V3 design references distinguish object, component (ID and type), transform, asset and runtime service. Resolution checks run after all objects are indexed, so forward references work. Cross-room scene references are rejected. Component type and instance ID are checked together; a `BaseBlock` beside an `AirVentBlock` is not guessed from a shared base class. Asset localFileId is a string.

The 21 source UnityEvent calls are stored in their original order and retain target component, method, call mode, arguments and call state. UI calls are marked `runnerUi`; gameplay calls are `levelDesign`. Level3's `Button 返回主菜单` calling `NextLevel` is retained with `nameMethodMismatch`, pending Unity verification. These records are source evidence, not executable V3 event rules.

## Version and loss boundary

V1 and V2 files and adapters stay unchanged. `openLevelWithoutMigration` dispatches by explicit `formatVersion`; it does not write or upgrade any source. V3 has full local quaternion rotation, separate RectTransform data, typed refs, stable component and event IDs, and `sourceOnly` components for unmigrated serialized data. Schema and semantic validation reject unknown top-level/object/event fields, unsupported registered component versions, missing targets and false `full` coverage. A source-only component stores a hash and points back to the unchanged source scene; it cannot be saved as an independently reconstructable component. The M1.2 exporter must either capture all significant serialized fields and dependencies or continue to reject full migration. V3 is not yet connected to the desktop editor, Unity importer or player.

`Levels/Resources/ResourceSources.json` records source GUID and string localFileId, source kind (project asset, code, Unity built-in or package), type, known source path/hash, usage and future package path. All entries are `sourceOnly`; no pack contents are claimed.

## M1.2 gates

1. Export all A/B objects and relevant D scene settings with exact Unity values, UI coordinates, component order and reference semantics; preserve or explicitly reject unknown fields and components.
2. Define verified template/config binding for every C object and preserve the original non-GameObject scene settings.
3. Resolve assets and Unity built-ins for a portable runner package. The source manifest is dependency provenance, not bundled bytes.
4. Convert each gameplay UnityEvent only after target method semantics are mapped; retain the flagged Level3 UI call until Unity verification.
5. Reconstruct in an isolated Unity scene and compare normalized data and behavior before any room changes from `sourceOnly`.
