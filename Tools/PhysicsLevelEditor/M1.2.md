# M1.2: read-only source export

Run `python Tools/PhysicsLevelEditor/tools/export-v3-drafts.py` from the repository root. Python 3 with PyYAML is required for this development-only exporter. It refuses any Scene whose SHA-256 differs from `Levels/ProjectManifest.json`, duplicate YAML keys, unmapped GameObjects/components, unresolved fileIDs or assets, changed source document hashes, broken hierarchy/order, or different existing output. `--update-generated` can replace only its own earlier M1.2 candidates for the same source Scene; the normal command never rewrites them.

The three candidates are in `Levels/Drafts/M1.2/`. They contain all source GameObjects, components and five non-GameObject scene documents per room. Each Unity YAML document has its original text, byte hash, source order, class ID, fileID and parsed fields. Reassembling those documents with `sceneConfig.sourceHeader` yields exactly the original Scene bytes. Parsed fields exist for inspection; the raw text is the lossless authority. Unknown components and fields are `sourceOnly`, with original type and document retained. They are **not** verified Unity runtime adapters.

The `sourceReferences` arrays use stable object/component IDs and asset IDs. Field paths and array indices retain original order; explicit `fileID: 0` is `null`. The original 21 UnityEvent calls live in `sourceCalls`. Six Level3 gameplay calls also have `source.unityPersistentEvent` design-source entries. These entries describe provenance and **cannot execute**. The fifteen UI calls remain source records for future runner template binding. Level3's button named “返回主菜单” still calls `NextLevel` and carries a review flag.

`coverage: exportedUnverified` means complete source-document capture and static validation only. All three ProjectManifest rooms remain `sourceOnly` with no levelDataPath. The drafts are not available to the desktop editor, Unity importer or player. V1/V2 files, Schema and adapters are unchanged.

`Resources/ResourceSources.json` gained three Unity built-in references from RenderSettings/LightmapSettings: spot cookie, skybox material and lighting data asset. They have GUID and string localFileId, with no claimed package file. No resource pack was built.

## Verification boundary

`npm.cmd run check` verifies source IDs, ownership, original YAML byte reconstruction, resource/reference targets, events, V3 Schema, corruption refusal and V1/V2 regressions. `npm.cmd run build` validates TypeScript/Electron build. Neither command runs Unity. M1.3 must implement and verify a Unity reconstruction path, exact built-in and package asset handling, runner system templates, supported component adapters, and behavior tests before any room can be called editable or playable.
