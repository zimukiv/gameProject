方法：逐像素量测（标题栏、HUD 带、世界层起始行、纯黑区、底部叠加元素包围盒），并与 `ApplyScreen()` 的设计空间换算互相验证。

## 三、需要处理的两处

### 3.1 底部提示盖住关卡（#3）

- 现状：提示条是覆盖式，直接画在关卡上方，位置在设计 y 363..385（屏底往上约 60px）。
- 影响：60×60 这类大房间里，底部两行地形会被文字压住；文字压在亮色地形上时可读性会下降。
- 备选方案（含代价）：

| 方案 | 做法 | 代价 |
| --- | --- | --- |
| A 预留底部带（与顶部对称） | 世界层再让出 30 设计像素（单行 12px + 边距，可容纳两行） | 可视关卡高度 399 → 369（-7.5%）；叠加顶部后总量 -15% |
| B 提示自动淡出 | 无提示内容 3 秒后淡出，有内容（复活/交互/温区/开发检查）才显示，透明度 0.85 | 需要时仍会短暂压住关卡 |
| C 半透明底衬 + 只在必要时显示 | 提示加 55% 深色底衬，且仅在 RespawnRemaining>0 / NearbyInteraction!=null / ThermalHint!=null / tainted 时显示（普通"已进入房间"等消息改到 HUD 条） | 改动小，观感提升明显 |

**建议 C**：底部只保留"当前必须知道的交互信息"，其余消息进顶部状态条；这样既不再长时间压住关卡，也不用牺牲 7.5% 视野。

### 3.2 引擎水印（#4）

- 现状：包是带 `BuildOptions.Development` 构建的，Unity 会在右下角画 "Development Build" 水印，且开发版有额外开销与调试钩子。
- 建议：群测包改用 `BuildOptions.None` 发布；需要诊断时再单独出开发版。改动一行（`Editor/NativePhysicsDemoEditor.cs` 的 `BuildPlayer` options），构建后水印与开发开销一并消失。

## 四、自动化覆盖的盲区（需要补的断言）

现有矩阵只校验「UI 控件之间」的矩形重叠、越界与文字裁剪，以及世界层覆盖整个窗体；它**看不见「UI 覆盖关卡」**，因为世界层被标记为装饰层跳过比对。要防回归，建议补两条结构性断言：

1. `worldRect` 必须严格等于「设计空间减去已声明的顶部/底部预留带」——这样任何"少让出/多让出"都会被抓到。
2. 声明式 UI 覆盖清单：若某 UI 元素（提示条、水印区）与 `worldRect` 相交，必须在清单里显式登记（例如"提示条允许覆盖，但面积占比 ≤8%"），否则判为问题。

## 五、结论

- 顶部黑条挡关卡的问题**已修好**：实测 HUD 条与关卡零重叠，关卡从 HUD 带下方开始完整显示。
- 仍然存在的重叠只有两处：**底部提示文字**（设计内叠加，建议按 3.1 方案 C 收敛）与**引擎开发版水印**（建议按 3.2 改发布构建）。
- 布局换算、世界层铺满、无信箱黑边均验证通过；纯黑占比 1.72% 且全部来自顶部 7 设计像素边距。
