# 2026-10-18 优化记录

## 本轮变更

- 检查点通过 `ICheckpointState` 保存机关快照。签到数与颜色、门的位置及运动目标、启动装置、距离开关、清醒块、导航标记、移动/消失平台、冰块计时和冷热/积分模式随死亡回滚。快照只扫描当前场景，在同一次遍历中记录拾取物和机关。
- 初始快照在普通组件 Start 初始化后记录；签到静态计数先清零再保存。复活先恢复状态，再发出复活事件，AI 和 HUD 读取最终阶段。角色会脱离移动平台，重置蹲伏碰撞体与临时速度效果。
- 加速与减速使用独立的限时倍率，不再覆盖基础 moveSpeed；同一来源重复触发只刷新，多个来源按倍率相乘，各自到期。时间使用 Unity 游戏时间，暂停时不消耗效果时长。
- AI 遍历已启用导航标记的注册表；抵达标记后取消其引导，避免停在标记处。距离机关与收藏品复用当前关卡 AI 引用，取消每帧全场景搜索。
- 玩家、Esc 和机关交互共用 GameInput。生成器按当前输入后端选择 UI 输入模块；已生成场景更换后端时需同步修改 EventSystem。当前 manifest 仍只安装 UGUI，当前配置仍使用旧版输入。
- 热控按冰块组件而非启用中的碰撞体查找目标；热态保持融化，冷态能重新启用已禁用的碰撞体。冰块和消失平台使用可保存的剩余计时，避免死亡后旧协程继续改写状态。
- 电磁炮临时接管角色运动，正常输入不再争用导轨；死亡/禁用时取消导轨协程，弹射后恢复角色原始重力配置。

新增机关若需要死亡回滚，应实现 ICheckpointState；快照是当前场景内存状态，退出或重载关卡仍从关卡起点开始。不要在 RestoreCheckpointState 中重放得分或开门事件；被驱动对象应保存自己的状态。

## 第二轮修复：持续接触、分数与物理更新

- 玩家伤害和 AI 杀伤增加持续接触检测。保护期判定交给独立 InvulnerabilityWindow：保护结束后允许再次判定，不要求玩家离开后重新碰撞。
- 持久存档数据移至 GlobalSaveData，JSON 字段保持不变。规范化时已结算分数仅限制为非负，不能被未通关阶段的扣分压低；最高分至少覆盖当前和已结算分数，保留旧存档补齐规则。
- 旋转机关同时处理 Collision 和 Trigger，按命中的角色决定玩家弹射或 AI 击退。AI 击退取消正在执行的技能，在持续时间内优先于追击，死亡/重置时清理。
- PlayerController 在 Update 采样输入，在 FixedUpdate 消费并写入刚体速度。输入边沿只消费一次，冲刺方向按按下时记录。DashMotion 计算每个物理步中的实际行进距离，处理最后不足一步的时长；AI 追击和旋转刚体也迁移到固定更新。
- 实时分数和音量分别使用 1 秒/0.5 秒的合并写入窗口。连续修改不会无限延后截止时间。存档失败保留待写状态并限频重试；正常暂停、返回菜单、退出立即刷新，通关和全屏切换即时保存。强制结束进程可能丢失最近窗口内未写盘的实时修改。
- 加载关卡前检查场景是否存在，再改变分数与索引；不可加载时给出错误。

本轮旧版/新输入条件编译均为 0 错误、0 警告；回归直接引用实际业务类，扩展到 59 项断言，覆盖分数规范化、输入消费、不同步长的冲刺距离、延迟写入与重试调度、连续接触的保护窗口，以及原有速度效果。几何检查通过。

这些独立检查不运行 Unity 碰撞系统或实际磁盘 API。此前记录的 headless 许可缺失仍未解决；Unity 触发器、击退、帧率手感和正常退出落盘仍需按 PLAYTEST.md 实测，不能标记为运行验收通过。
