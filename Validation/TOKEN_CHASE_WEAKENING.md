# Token 削弱 AI 追逐速度（2026-10-25）

用户确认：追逐前多捡 Token，应更多削弱 AI 的速度，使追逐更轻松；但全收集后 AI 也必须明显快于玩家普通跑速，保持追逐意义。此前的 `基础难度 + Token × 0.1` 方向相反，已替换；旧体验基线中的速度表仅用于记录问题。

## 当前规则与暂定数值

启动 AI 时仍投入全部持有 Token，只结算一次。追逐速度倍率为：

`baseDifficulty × max(0.7, 1 / (1 + 持有 Token 单位数 × difficultyPerToken))`

根据用户进一步确认“全收集后也必须明显快于玩家”，三关基础常速从 10 提高到 14，减速下限从基础速度的 25% 提高到 70%；每单位减速强度仍为 0.03，基础倍率为 1。玩家无增益跑速保持 8。当前数值：

| 启动时投入 Token | AI 常速 |
| --- | --- |
| 0 | 14.00 |
| 3 | 12.84 |
| 5（一个大 Token） | 12.17 |
| 7 | 11.57 |
| 12（物理关全收集） | 10.29 |

曲线与数值仍是待实玩调整的参数。物理关全收集后 AI 常速约比玩家快 29%，少收集时更快；准备收益是减轻追逐压力，不能靠普通直跑持续拉开距离。当前 Demo 的 0–12 单位内，每单位均进一步减速。15 单位起到达速度下限 9.8，仍比玩家普通跑速高 22.5%，防止更多 Token 把 AI 降到玩家以下。

- 普通 Token 算 1 单位，大 Token 算 5 单位；满冲刺槽后拾取的 Token 仍计入启动减速。
- 使用冲刺不消耗持有 Token，因此启动前使用冲刺不会减少已积累的 AI 减速收益。
- AI 启动仍不赠送冲刺，也不清除已有次数或部分充能；3 单位充一次、容量 1、满充不囤能量的规则全部保留。
- 减速结算发生在启动时。启动后收集的 Token 仍计分和充冲刺，不追溯改变已经结算的 AI 速度。
- AI 常速和物理关爆发冲刺速度都应用该倍率；技能距离、冷却、持续时间不变。高数牵引保持基础力度 9，不再用速度倍率缩放玩家受到的牵引；水课减速技能参数不变。
- 检查点沿用现有 `aiDifficulty` 快照保存速度倍率，追逐阶段复活恢复该倍率；探索阶段复活后重新收集/启动结算。

## 接口记录（供 B 后续对接）

没有改变编辑器工具或关卡 JSON。纯逻辑 `Assets/Scripts/AI/TokenChaseSpeed.cs` 是公式入口，速度倍率下限改为 0.7。本次调速同步更新了三关序列化的 `baseChaseSpeed` / `currentSpeed`（14），保留 `difficultyPerToken`（0.03），并同步脚本默认值、场景生成器；未重建场景或修改路线几何。

`AIActivatorDevice.baseDifficulty`、`difficultyPerToken` 保留字段名与现有序列化值，避免丢失场景配置；其中 `difficultyPerToken` 的正值语义由“增加难度”改为“增加减速强度”。`EventBus.OnAIActivated` 的第二个参数、`GameManager.currentAIDifficulty`、`EnemyAI.difficultyMultiplier` 和检查点 `aiDifficulty` 保留名称/类型，本轮开始表示投入 Token 后的追逐速度倍率。后续任何适配器不要再次套用旧的加法公式。
