## 已确认的现状

三关实际序列化的玩家跑速均为 8、跳跃初速 15、重力倍率 3；不能用 PlayerController 字段默认值 10/19 判断当前关卡。忽略碰撞和加速时，普通跳跃最大上升约 3.82，等高水平距离约 8.15。冲刺理论位移约 4.29，但结束时速度清零，再按移动加速；是否有明显顿挫需实玩。

| 项目 | 物理 | 高数 | 水课 |
| --- | --- | --- | --- |
| 普通 Token | 7 枚，全在启动点之前 | 7 枚，均在 x=11 启动点之前 | 同高数 |
| 大 Token | 5 单位，x=31.5，启动点 x=33 | 5 单位，x=19，位于启动点之后 | 同高数 |
| AI 启动 | 靠近按 E，有提示 | 接触启动 | 接触启动 |
| 检查点 x | 6、23，均在启动前 | 4.5、16.8，跨启动点 | 同高数 |
| AI 常速 | `5.5 × (1 + 持有 Token × 0.1)` | 同物理 | 同物理 |

只按位置统计资源，不代表沿地面行走即可全部拾取；空中 Token、大 Token 的实际获取路线仍需验证。

冲刺满充后多收的 Token 不存下一次能量，但仍保留给 AI。当前 AI 难度沿用原公式，因此：

- 持有 0 / 3 / 5 / 7 / 12 单位启动时，AI 常速依次为 5.5 / 7.15 / 8.25 / 9.35 / 12.1。5 单位起已超过玩家无增益跑速 8。
- 物理关全收集时可带 12 单位启动；启动点后没有新 Token，冲刺用完不能沿后续主路再次充能。喷气、电磁炮、1 秒启动延迟与路径差异会影响结果，不能仅凭速度宣称不可通关。
- 高数、水课按正常向右前进、启动前收完普通 Token 的情况为 7 单位；后段大 Token 可补一槽。返程或绕过启动器会改变资源顺序，应另记为特殊路线。
- 水课 AI 的近身技能会使玩家速度乘 0.65，持续 1.5 秒（无其他效果时约 5.2）。必须连同等待 AI 开门的过程验证，不能只测空地直跑。

## 建议的实施顺序

### 1. 先完成一轮有针对性的三关试玩

优先验证物理关“多收集、早用冲刺”的容错，以及水课“漏签到、回头补签”的恢复成本。保留现有参数记录结果，再决定改资源位置、提示还是追逐参数，避免一次同时改多个变量。

| 试玩用例 | 操作 | 记录与判断依据 |
| --- | --- | --- |
| 物理基础路线 | 不用冲刺完成冰阶与喷气；收大 Token，E 启动后走地面到出口 | 是否必须靠冲刺补救主路；启动 Token 数、冲刺状态、死亡点、通关时间 |
| 物理资源压力 | 尽可能收齐 12 单位；启动前用掉冲刺，与保留冲刺的一次对照 | 满收是否反而显著难于少收；电磁炮前后是否有稳定脱险窗口 |
| 物理可选路线 | 已能稳定通关后再引 AI 去周期平台与收藏品 | 可选目标是否明确；等待窗口、失败后的重跑时间；不把收藏失败计为主路失败 |
| 高数主路 | 记录实际启动 Token；保留/提前消耗冲刺各跑一次，尝试拿后段大 Token | 积分平台用途是否看懂；旋转机关和 AI 牵引是否形成连续失控；大 Token 是否可可靠取得 |
| 水课顺序 | 完整签到一遍；再故意漏一个签到块后回头补签 | 第五个签到与自动启动是否同时发生；补签是否变成被追逐时的强制折返 |
| 水课终段 | 分别带有/没有冲刺到 AI 开关，等待 AI 靠近开门 | 等待位置是否安全；玩家是否看懂“把 AI 引来”；减速是否让开门成为必死点 |
| 每关失误恢复 | 启动前、启动后各故意死亡；核对资源、拾取物、机关状态与阶段 | 物理回探索；高数/水课按保存阶段恢复；失败到再次尝试同一障碍的耗时 |

每次记录：关卡、路线、启动 Token 数、启动时冲刺次数/部分充能、用冲刺位置、死亡位置/原因、重试耗时、是否通关。不同资源路线不合并统计；首次理解失败与理解后操作失败分开记录。使用隔离存档；不要清除正常试玩存档。完整流程仍以 [PLAYTEST.md](PLAYTEST.md) 为准。

### 2. 最小体验改动优先考虑机制辨识

- **冲刺反馈**：在现有单槽上明确显示三个充能段，并给充满/空槽按 Shift 的短反馈；满充拾取需让玩家理解“计分和 AI Token 仍增加”。规则不变。当前 HUD 有单槽和数字，尚无三个独立充能段。
- **交互提示**：物理的温控/AI 按 E，高数的积分块踩踏、水课的签到踩踏与启动器接触，应各自说明触发方式，避免玩家把物理关学到的 E 泛化到所有机关。高数/水课启动器当前未启用物理关同款引导。
- **水课进度**：显示签到 n/5、门的开启条件，以及 AI 开关需要 AI 靠近的状态。当前签到已有事件与颜色反馈，但 UIManager 没有订阅签到事件，缺少全局进度显示。

这些是下一轮候选改动，本次尚未实施。优先让玩家知道失败原因，再依据实玩记录平衡难度。

### 3. 再处理手感与关卡节奏

- 当前跳跃要求物理步时已经着地；输入缓存只跨 Update/FixedUpdate，没有土狼时间或落地前跳跃预输入窗口。先测冰阶边缘起跳和落地连跳；如果确有漏跳，再小范围试验宽容窗口，并验证暂停、死亡、导轨不会补发旧按键。
- 记录冲刺结束清零造成的顿挫、喷气后的反向修正、冲刺后落台，先单独测试，避免同时调加速度与跳跃高度。
- 水课第五个签到块中心 x=10.8，自动启动器中心 x=11，签到门 x=13.5。二者接触区域相邻/重叠，不能把“签满五次后安全准备再启动”当作当前体验。根据实玩决定是否需要安全准备区；暂不更改启动方式或门序。
- 高数积分/求导机关改变的平台位于后段，玩家在前段操作时可能不明白影响对象。先确认视野和提示；暂不重设计路线。
- 若确认多收 Token 导致显著惩罚，再比较启动前难度预告、追逐参数校准、追逐段补充 Token 的方案。不得自动补冲刺、囤能量或修改大 Token 的 5 单位规则。
