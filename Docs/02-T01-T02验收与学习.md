# T01 与 T02 动手验收

这次先让一个占位玩家在测试场景里稳定跑跳。地图是测试台，不是 T07 的完整关卡。按顺序完成以下两次小验收后，再接 T03。

2026-10-14 已用 6000.6.4f1 实际编译并运行 4 项 Play Mode 自动验收，全部通过：移动/停止/相机、单跳/落地再跳、墙面/顶棚碰撞、测试重置。自动验收不能代替你的手感判断。测试代码位于 `Assets/_Game/Tests/PlayMode`，可以在 Unity 的 Test Runner 的 PlayMode 页运行；它只在测试期间调整输入焦点设置，结束后恢复。

## 小步骤一 验收共同工程

1. 在 Unity Hub 中 Add project from disk，选择 `D:/minigame/UnityProject`，用 6000.6.4f1 打开。
2. Project 窗口展开 `Assets/_Game`，确认有 Scenes、Scripts、Prefabs、Config、Input、Art 和 Audio。
3. 打开 `Scenes/A_GameplayTest`。Hierarchy 应有 Player、Main Camera、Ground、三块 Step、Wall、LowCeiling 和测试出生标记。
4. 查看 Console，等待导入/编译结束。不得有红色错误。工程采用内置渲染管线，暂时不引入 URP 灯光和正式美术。
5. Edit > Project Settings 中确认 Editor 的 Asset Serialization 为 Force Text，Version Control 为 Visible Meta Files，Player 的 Active Input Handling 为 Input System Package (New)，Time 的 Fixed Timestep 为 0.02。
6. Layers 中 Ground 为第 8 层、Player 为第 9 层。不要把可站立的平台留在 Default 层。

已经建立本地 Git 仓库及 Unity 忽略规则，没有创建远端或推送。策划案会保留；Word 的临时锁文件不会进入仓库。初次打开时生成的 Library、Temp、UserSettings 不要交给 B。

## 小步骤二 验收跑跳

点击 Play，再点击 Game 窗口获得输入焦点。蓝色方块是玩家；灰色形状是地面、台阶、墙和低顶。

| 操作 | 预期 |
| --- | --- |
| A/D 或左右键，松开 | 左右移动；松开立即停止水平移动，重力仍正常作用 |
| 同时 A+D | 水平方向抵消 |
| 空格或 W，持续按住 | 只跳一次，落地后不会因仍按住而自动重复跳 |
| 腾空后松开再按跳跃 | 不会二段跳；必须落地后重新按 |
| 向右跳上三块台阶 | 每个台阶可站稳，落地后可继续跳 |
| 持续向右撞墙 | 被墙阻挡，不旋转；墙边腾空时不能借墙再次跳 |
| 向左进入低顶区域后跳跃 | 碰到顶后落下，不穿过顶棚 |
| 移动离开初始画面 | 相机平滑跟随，仍是正交 2D 视图 |
| R，或向左越过地面边缘并掉到 y < -8 | 回到测试出生点；这是临时工具，不是检查点系统 |
| Stop，重新 Play | 返回场景最初状态 |

验收时先看“是否正确”，再记录手感，例如“移动太快”“跳得太高”“相机跟得慢”。当前没有加减速、土狼时间、跳跃缓冲、可变跳高或蹲下。数值只用于原型，不代表最终设计。

## 选中 Player 看组件

Player 场景对象来源于 `Prefabs/Player.prefab`。挂载已完成，下面是你以后自己组装对象时需要理解的关系。

| 组件/字段 | 当前值/引用 | 为什么 |
| --- | --- | --- |
| Transform | 起点 (0, 0, 0)，Scale (1, 1, 1) | 缩放只放在 Visual 子物体，避免改变玩家碰撞体 |
| Layer / Tag | Player / Player | 与地面层分离；Tag 供后续查找玩家 |
| Rigidbody 2D | Dynamic，Mass 1，Gravity Scale 3 | 用 2D 物理负责下落和碰撞 |
| Rigidbody 2D | Interpolate、Continuous、Freeze Rotation Z | 平滑显示，减少快速穿透，防止玩家倒转 |
| Capsule Collider 2D | Size (0.8, 1.6)，Is Trigger 关闭 | 胶囊侧面较不易卡住台阶边缘；实体碰撞 |
| Collider Material | Player_NoFriction | 摩擦 0、弹性 0，减少贴墙停滞或碰地弹跳 |
| Player Input Reader / Controls | PlayerControls | 读取 Input Actions，不需要再挂 PlayerInput |
| Player Motor 2D / Settings | PlayerMovement_Default | 读取 B 管理的移动配置 |
| Player Motor 2D / Ground Layers | 只勾 Ground | 只把平台认作地面 |
| Player Motor 2D / Ground Probe Distance | 0.06 | 将碰撞体向下探测一小段；墙的侧面法线不算地面 |
| Sandbox Reset / Fall Limit | -8 | 只挂在测试场景实例，未放进复用预制体 |

Visual 子物体的 Sprite Renderer 使用白色 Square 占位图，着色为蓝色，Scale (0.8, 1.6, 1)，Sorting Order 1。美术以后可替换 Visual，不必重写刚体脚本。

## 脚本在做什么

- `PlayerInputReader.cs` 把“按哪个键”与“玩家怎么运动”分开。Move 读取水平轴；Jump 把一次按下记下来，等待下一次物理更新消费。该记号不是长时间跳跃缓冲，腾空时也会消费掉。每个玩家克隆输入资产，避免共享 Enable/Disable 状态。
- `PlayerMotor2D.cs` 在 FixedUpdate 中探测地面，再写 Rigidbody2D.linearVelocity。X 是输入乘移动速度；跳跃只改 Y 为跳跃初速，随后交给重力。用碰撞体向下 Cast，并检查接触法线朝上，避免将墙认作地面。
- `CameraFollow2D.cs` 在 LateUpdate 中跟随玩家的显示位置，用 SmoothDamp 缓动，固定 Z=-10。它不参与物理。
- `PlayerMovementSettings.cs` 是 ScriptableObject 配置定义；它本身不运动，也不挂在场景对象上。配置资产集中保存四个值，由 B 维护，A 提出调参需求。
- `SandboxReset.cs` 只在测试场景方便重新尝试；T04 换成 B 的检查点重试。它没有 token、积分、AI 或存档数据。
- `PrototypeSetup.cs` 是 Editor 工具，一次性生成初始场景/配置/预制体；菜单 Minigame 中可见。工程已生成后不要再运行；工具会拒绝覆盖已有初始资产。它不会随游戏运行。

现在只由 PlayerMotor2D 写常规移动速度。T03 增加冲刺时要让同一个运动控制流程决定本帧速度，避免移动和冲刺脚本每帧互相覆盖速度。

## 摄像机和配置 Inspector

选 Main Camera：Projection 为 Orthographic，Size 5；Camera Follow 2D 的 Target 指向 Player，Offset (2,1)，Smooth Time 0.15。没有 Cinemachine 依赖。

选 `Config/PlayerMovement_Default`：Move Speed 7、Jump Speed 12、Gravity Scale 3、Max Fall Speed 20。这些均是临时建议值。可在本地尝试修改，但 Stop 后配置资产可能仍保留修改；请记录原值，与 B 沟通后再提交。Rigidbody 的 Gravity Scale 运行时由配置写入，调手感请调配置，避免在两处维持不同的值。

选 Ground/Step/Wall/LowCeiling：Layer 必须为 Ground，Box Collider 2D 的 Is Trigger 关闭，普通静态平台不加 Rigidbody 2D。复制平台时保持这些设置。
