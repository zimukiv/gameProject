## B03 核心模块与接口

建议新增 `Scripts/Systems/RunResources.cs`，命名空间 `Minigame`。作为 MonoBehaviour 挂在场景中唯一的 `Systems` 对象上，用 Inspector 引用 Resource_Default。A 的玩家或 UI 获得这个实例的引用后调用；无需在这批引入全局单例或复杂注入框架。

本任务单采用以下接口。B 如需改动名称或签名，请先反馈差异，双方对齐后再接入。

```csharp
int TokenCount { get; }
bool HasFreeDash { get; }
bool IsAIActive { get; }
void BeginLevel();
void AddTokens(int amount);
bool TrySpendDashResource();
bool ActivateAI();
event System.Action ResourcesChanged;
```

| 接口 | 具体行为 |
| --- | --- |
| 三个只读属性 | 查询 token、未用免费机会、本轮 AI 是否已启动；外部不能直接赋值 |
| BeginLevel | 新进入关卡时 token=0、无免费机会、AI 未启动；通知一次，便于 UI 同步初始值 |
| AddTokens | 正数增加 token 并通知一次；0 不改变状态；负数抛 ArgumentOutOfRangeException，不改变状态 |
| TrySpendDashResource | 先用免费机会；否则 token 足够时扣 dashTokenCost；成功返回 true 并通知一次，失败返回 false且不改变状态 |
| ActivateAI | 首次成功时清空剩余 token、免费机会设为一次、AI 标记设为已启动；通知一次；重复调用返回 false，不再赠送 |
| ResourcesChanged | A 的显示脚本订阅事件后读取属性；B 不在事件里直接修改 A 的 UI |

BeginLevel 由关卡进入流程明确调用；测试场景用测试脚本调用，后续由 B 的关卡管理调用。不要把“新关归零”当成任意重启脚本都应执行的操作。T04 的死亡重试将恢复检查点快照，届时另接恢复接口。

当前没有统一 GameState，先由 RunResources 持有本轮 AI 标记。如果 B 同期已经建立 GameState，请明确一个唯一拥有者，RunResources 不重复保存同一标记。`ActivateAI()` 在本阶段只结算状态与资源，不生成敌人、不控制敌人运动。

## A 与 B 各自控制什么

| 流程 | A 负责 | B 负责 |
| --- | --- | --- |
| 收集 token | 玩家碰撞、收集物显示/消失；调用 AddTokens | 参数与 token 数据变更 |
| 发起冲刺 | 输入、方向、动作可用性、本次腾空次数、冲刺速度和持续时间 | TrySpendDashResource 的资源结算 |
| 启动 AI | 启动装置互动、敌人启动与追逐表现 | 清空 token、赠送一次免费机会、记录启动状态 |
| 落地 | 重置本次腾空冲刺计数 | 保留现有 token 与未使用的免费机会 |
| 显示资源 | 订阅事件、读取属性、显示数字和效果 | 发布状态变化事件 |

A 先检查动作可用且腾空次数不足三次，再调用 TrySpendDashResource；成功后才执行冲刺并增加次数。免费冲刺也计入三次额度。B 不因为玩家落地补资源，也不另存一份冲刺次数。AI 启动前后都允许按相同规则支付冲刺资源。

## B04 独立测试场景

在 B_SystemTest 中新增 Systems 并挂 RunResources，配置引用 Resource_Default。提供一个测试脚本，能在运行时触发 BeginLevel、添加普通 token、添加大 token、请求冲刺和启动 AI。用简单日志或临时测试面板显示三个状态与操作返回值即可。

测试入口读取配置中的增量，不硬编码 1/5/2。测试脚本只调用资源模块，不直接写 token 或免费机会；只挂 B 的测试场景，不挂 Player.prefab，也不放进正式关卡。

## B05 验收用例

每组用例重新 BeginLevel，避免上一组状态影响下一组。下面价格用默认值 2，测试调整配置时应验证实际读取新价格。

| 用例 | 操作 | 预期 |
| --- | --- | --- |
| 新关初始化 | BeginLevel | token=0，无免费机会，AI 未启动 |
| 资源不足 | 初始化后请求冲刺；再加 1 后请求 | 都失败，余额及免费机会不变 |
| AI 启动前可付费冲刺 | 加 4，依次请求三次 | 前两次成功，余额 2→0；第三次失败 |
| 启动结算 | 加 5，然后 ActivateAI | 首次 true；token=0，有一次免费机会，AI 已启动 |
| 防重复启动 | 再调用 ActivateAI | false；不再赠送免费机会，也不额外清空后来收集的 token |
| 免费机会优先 | 启动后加 2，再请求冲刺 | true；免费机会消耗，token 仍为 2 |
| AI 启动后可付费冲刺 | 在上一条后再请求 | true，token 扣为 0 |
| 可调价格 | 新关配置成本改为 3，加 2 再请求；然后加 1 再请求 | 第一次失败，第二次成功；测试后恢复默认成本 2 |
| 无效增量 | 加 0；再尝试加负数 | 0 无变化；负数被拒绝，状态不变 |
| 事件通知 | 记录事件次数 | 成功变更各通知一次；失败/重复操作和加 0 不通知；BeginLevel 通知一次 |
| 再进新关 | 先制造非零余额和免费机会，再 BeginLevel | 清空余额/免费机会，AI 标记重置 |

用 Unity Test Framework 编写这些资源规则的自动测试，既测试返回值，也检查操作后的状态。已有 `Tests/PlayMode` 测试程序集可引用 `Minigame.Runtime`；如果新增测试文件，保留原来的 PlayerSmokeTests。测试结构可按 B 的实现调整，交接时说明运行方式。

落地不补资源、一次腾空最多三次，是 A/B 联调验收项目；B 模块不监听地面或刚体来推断落地。B 的独立资源测试不需要实现玩家运动。
