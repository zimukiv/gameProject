## 建议的 T03 接口

```csharp
int TokenCount { get; }             // 当前 token；A/UI 只读
bool HasFreeDash { get; }           // 是否有未用免费机会
void BeginLevel();                  // 新进关：token=0、无免费机会、AI未启动
void AddTokens(int amount);         // 收集物向资源模块申请增加，拒绝负数
bool TrySpendDashResource();        // 免费优先；否则检查/扣 token；失败时不修改状态
bool ActivateAI();                 // 一次成功启动：清空 token、给一次免费机会
event System.Action ResourcesChanged; // 值变化后通知 A 的 UI
```

`ActivateAI()` 这里只管理启动状态和资源结算，不实现敌人移动。建议成功返回 true，已经启动时返回 false，不再次扣费或赠送机会，防止触发器重复进入导致无限赠送。若项目中已有统一 GameState，应由它保存 AI 启动状态并防重复，资源模块不再另存第二份；请在返回说明中明确唯一状态拥有者。

`BeginLevel()` 与未来的检查点恢复是两个操作。进入新关要归零，死亡后则恢复检查点快照；这批不实现检查点恢复。

资源状态建议放在场景中的一个 Systems 对象，由 B 说明创建和引用方法。配置 ScriptableObject 只保存参数，不保存当前 token 或免费机会。不要在玩家脚本、UI、收集物以及配置资产各保存一份资源状态。

## 与 A 的调用边界

A 判断是否处于可冲刺状态、输入方向和本次腾空次数是否不足三次。只有这些条件满足，才调用 `TrySpendDashResource()`；返回 true 后启动冲刺并增加腾空计数，false 时不执行冲刺。

B 只处理免费机会及 token 的检查和结算。B 不保存冲刺速度、方向或本次腾空次数。落地由 A 将腾空计数重置为 0，B 的 token 和未用免费机会不变化。免费冲刺也计入 A 的本次腾空计数。UI 监听状态变化并读取属性，不直接扣费。

W 跳跃与向上冲刺的输入优先级由 A 在 T03 处理；B 不修改输入资产。

## B 的验收用例

| 步骤 | 应得到的结果 |
| --- | --- |
| BeginLevel | token=0，无免费机会 |
| 没资源时请求冲刺 | 返回 false，资源不变 |
| 加 4 token，连续请求三次 | 前两次成功，各扣 2；第三次失败 |
| 加 5 token，启动 AI | token 清零，免费机会为一次 |
| 已启动后重复调用启动 | 不再赠送免费机会 |
| 获得免费机会后再加 2 token，请求冲刺 | 先消耗免费机会，token 仍为 2 |
| 再请求冲刺 | 成功扣 2，token 为 0 |
| 玩家落地 | token/未用免费机会不补充；只有 A 的腾空计数重置 |
| 再 BeginLevel | 资源及启动状态按新关初始化，不继承上关 |
